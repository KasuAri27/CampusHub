编写：卫苏协议小组       日期：2026-04-15

## 2. 总体描述

### 2.1 产品视角

大学校园内学生互助需求频繁，但现有解决方案（微信群、QQ群、贴吧）存在信息分散、匹配效率低、信任机制缺失等问题。

本平台旨在整合需求，提供高效、安全的互助服务。

（AI 生成）

### 2.2 用户特征

| 用户 | 特征 |
| --- | --- |
| 需求方 | 有临时需求，对效率、安全性敏感 |
| 服务方 | 利用碎片时间赚取报酬，无偿回答问题 |
| 管理员 | 审核内容，维护平台秩序，处理纠纷 |

（AI 生成+人工修改，AI 生成过于泛化，人工修改为具体身份具体特征）

### 2.3 约束

• 技术栈：前端：React Native/Flutter，后端语言：Java，工程构建：Maven，数据库：MySQL，开发环境：IntelliJ IDEA，持续集成：GitHub Actions

• 合规性：需符合《网络安全法》《个人信息保护法》。

• 部署环境：校园私有云或第三方云服务（如阿里云）（AI 生成+人工修改，修改了技术栈，将我们小组现实中用到的添加上去）

### 2.4 假设

• 假设校园Wi-Fi 覆盖良好，用户网络稳定。

• 依赖学校提供身份认证接口和第三方支付接口（如微信支付、支付宝）的可用性。

（AI 生成+人工补充，补充身份认证的依赖）

## 3. 功能需求

### 3.1REQ-001 身份认证

学生使用学号/手机号+验证码完成认证，仅认证通过者可发布或接单（人工补充）

### 3.2 REQ-002 需求发布

#### 3.2.1 功能描述

用户可填写需求类型、标题、描述、时间、地点、报酬（可选）等信息并发布。

#### 3.2.2 输入

• 需求类型（快递代取/学习辅导/二手交易/组队匹配/问题咨询）

• 标题（文本，≤30 字）

• 描述

• 时间（日期时间选择器）

• 地点（地图选点或手动输入）

• 报酬（数字，可选）

#### 3.2.3 输出

需求卡片展示在首页，包含标题、报酬、时间、地点缩略信息。点开需求卡片，看到需求完整信息。

#### 3.2.4 异常处理

• 输入不合法时提示错误（如时间已过期）。

• 网络异常时保存草稿，网络恢复后提醒用户再次编写需求。

(AI 生成+人工修改，增加需求类型和输出内容，删除描述的字数限制，修改异常处理结果)

### 3.3 REQ-003 需求匹配

#### 3.3.1 功能描述

系统根据用户标签（如专业、兴趣）、需求描述、地理位置、时间等自动推荐匹配需求。

#### 3.3.2 输入

• 用户标签（如“数学专业”“篮球爱好者”）

• 空闲时间和服务区域

#### 3.3.3 输出

匹配列表按相关性排序，显示需求标题、匹配度百分比。

#### 3.3.4 异常处理

• 无匹配结果时提示“暂无相关需求”。

（AI 生成+人工补充，补充输入内容，将地点修改为区域范围）

### 3.4 REQ-004 接单管理

#### 3.4.1 功能描述

用户可浏览需求详情并接单，支持多用户竞争接单（先到先得或发布者选择）。

#### 3.4.2 输入

• 接单按钮点击

• 可选留言（如“我有电动车，可快速代取”）

#### 3.4.3 输出

接单成功通知，需求状态更新为“已接单”。

#### 3.4.4 异常处理

• 需求已被接单时提示“该需求已被接单”。

（AI 生成）

### 3.5 REQ-005 评价系统

#### 3.5.1 功能描述

交易完成后双方可互评，评价内容公开显示在用户主页。

#### 3.5.2 输入

• 评分（1-5 星）

• 评价文本（≤200 字），可添加图片

#### 3.5.3 输出

评价内容实时更新至用户信用分（满分100 分）。

#### 3.5.4 异常处理

• 恶意评价可举报，由管理员审核后删除。

（AI 生成+人工修改，修改输入内容）

### 3.6 REQ-006 支付集成

#### 3.6.1 功能描述

支持校内卡或第三方支付完成报酬结算。

#### 3.6.2 输入

• 支付方式选择

• 支付密码/指纹验证

#### 3.6.3 输出

支付成功通知，资金到账服务方账户。

#### 3.6.4 异常处理

• 支付失败时提示原因（如余额不足）。

• 服务方未收到报酬，可与管理员进行交流，由管理员查询原因并给出解决方法（AI 生成+人工修改，修改输出错误，补充异常问题处理）

## 4. 非功能需求

### 4.1 性能需求

• 响应时间：首页加载≤2 秒，搜索≤1 秒。

• 并发处理：支持1000 用户同时在线。

### 4.2 安全需求

• 数据加密：用户身份信息可选择加密，而登录密码、支付信息完全加密。

• 权限控制：用户仅能访问自己的数据。

• 防刷机制：限制单日发布需求次数（如10 次）。

### 4.3 可用性需求

• 新手引导：首次使用时提供功能教程。

• 多语言支持：默认中文，可扩展英文

• 99.5%正常运行时间（月维度）

### 4.4 可扩展性需求

• 支持未来新增需求类型（如拼车、借书）

• 支持屏幕适配，浏览器兼容（AI 生成+人工修改，增加安全需求的隐私保护，增加可扩展性需求）

## 5. 外部接口需求

### 5.1 用户接口

• UI 风格：简洁、年轻化，符合大学生审美。

• 主要界面：首页（需求列表）、发布页、个人中心、消息页。

• 设备兼容性：支持iOS/Android 主流机型。

### 5.2 硬件接口

• 依赖手机GPS 模块获取位置信息。

- 支持扫码功能（如二手交易扫码验货）。

• 支持照相功能，用照片确认交易成功。

### 5.3 软件接口

• 支付接口：微信支付/支付宝SDK。

• 地图接口：高德地图/百度地图API。

• 短信接口：阿里云短信服务（用于验证码）。

### 5.4 通信接口

• HTTP/HTTPS：用于前后端数据交互。

• WebSocket：实时通知推送。

（AI 生成+人工补充，补充硬件接口的照相功能）
