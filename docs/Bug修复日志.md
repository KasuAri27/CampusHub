Bug修复日志

Bug1：接单后未触发通知

| 项目   | 内容                           |
|------|------------------------------|
| 问题现象 | 服务方接单后，需求方未收到任何通知            |
| 根因分析 | 接单相关的方法中为调用通知的方法，跨模块流程缺失     |
| 修复方案 | 在接单事务中调用通知相关的方法，动态拼接通知的标题和内容 |
| 验证结果 | 接单后，需求方可以在通知列表中查看响应通知        |

Bug2:验证码倒计时结束后无法再次获取验证码

| 项目   | 内容                                                   |
|------|------------------------------------------------------|
| 问题描述 | 在点击“获取验证码”按钮后，按钮进入60秒倒计时，倒计时结束后，按钮不可再次点击，用户无法再次获取验证码 |
| 根因分析 | 未保存定时器ID，无法在重复调用时清楚之前的定时器                            |
| 修复方案 | 采用单一定时器管理+启动前清楚旧定时器的修复方案                             |
| 验证结果 | 点击“获取验证码”按钮后，倒计时正常启动，60秒结束后，按钮恢复可点击状态，用户可以再次获取验证码    |

Bug3：前端baseURL与请求路径重复/v1

| 项目   | 内容                                                                           |
|------|------------------------------------------------------------------------------|
| 问题描述 | 前端的baseURL中已有/v1，但请求路径中重复，导致在登录注册时出现404Not Found                             |
| 根因分析 | http.js中配置了baseURL:'/v1'，而业务代码中调用http.post('/v1/verification/send'),导致请求路径出错 |
| 修复方案 | 保留baseURL:'/v1'，移除业务代码请求路径中的/v1前缀                                            |
| 验证结果 | 修改后请求URL正确，成功被代理转发到后端，登录注册界面可以正常使用                                           |
